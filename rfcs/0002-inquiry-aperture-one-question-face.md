# RFC 0002: Inquiry Aperture — One Question Face

Status: **proposed / owner review required**  
Date: 2026-08-16

## 1. Summary and status

YAWN's primary human aperture should present one situated Question. The
portable `.yawn` holarchy remains the invisible navigational and proof
substrate. This proposal changes no canonical state or deployed route.

## 2. Current state and lacuna

Existing surfaces can expose cards, controls, ontology, and proof machinery
before the Question that matters now. No single resolver yet binds an Arena
snapshot and returns one replayable selected Question.

## 3. Proposed semantics and invariants

- `.yawn` preserves coordinates, provenance, holarchy, boundary, proof, and revisions.
- YAWN.ai proposes and ranks attributed candidate Questions; it owns neither truth nor closure.
- YAWN.bot asks, captures, and offers only bounded actions.
- Q-Space is a rebuildable history View; Nestheads is an optional symbolic View.
- J-Space is an optional interpretability lens, not V1's source of truth.
- The person remains the sovereign Agent. "Jarvis" is a product metaphor for
  externalized orientation, not human-machine equivalence or a consciousness claim.

```text
selected Question
→ exact human answer Source
→ attributed human Projection
→ attributed Observation linked observed_from that Projection
→ Arena reorientation
→ deterministic rank receipt
→ next Question or explicit hold
```

An answer is not automatically truth, proof, preference, Yawn, Move, or
permission. Asking and answering are Agent Projections. Renderer, layout,
color, image, and navigation are Views.

## 4. Alternatives and counterexamples

An ontology browser, dashboard-first surface, ungrounded chat, opaque model
ranking, or art on the critical path does not satisfy this proposal. If no
Question meets the floor, the result is an explicit hold—not a fabricated claim.

## 5. Authority, privacy, safety, and human agency

Read-only inspection, deterministic local work, rebuildable Views, tests, and
effects already named in an approved work order do not require approval for
each command. Reusable grants remain bounded by scope, principal, budget,
expiry, revocation, and proof; confidence never expands them. New paid,
destructive, external, canonical/live-data, merge, deployment, or publication
effects require a grant. Each paid run still requires its own RunBudget.

## 6. Compatibility and migration

This is additive. Existing Q-Space types need Observation and rank-receipt
references before claiming conformance. Current art remains an optional View.

## 7. Schemas, examples, and conformance tests

The first deterministic slice must prove exact source/actor/Arena hashes,
multiple attributed candidates, one content-addressed rank receipt, one
Question before disclosure, idempotent Source → Projection → Observation,
replay stability, preserved alternatives, and an art-optional answer path.

## 8. Evidence, open questions, and falsifiers

Weights, acceptance floor, hold wording, and first supported coordinates remain
open. Unstable selection, collapsed actors, authority from score, duplicate
answers, or renderer dependency falsify the proposal.
