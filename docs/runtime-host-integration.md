# Integrate one bounded Runtime Profile path

Use Runtime Profile 0.1 unchanged as the compatibility baseline. The additive
[host contract](../spec/runtime-host-contract.md) supplies structural indexing,
action projection, current host checks, disclosures and conformance vectors.
It does not add the proposed 0.2 schema fields.

## Reuse and pin the implementation

The root package remains private. Its explicit exports support local/package
consumption; nothing in this change publishes it to npm. For vendoring, pin
the exact upstream commit and SHA-256 of every copied file:

- `lib/runtime-profile-v0.1.mjs`
- `lib/runtime-rule-events-v0.1.mjs`
- `lib/runtime-action-v0.1.mjs`
- `lib/state-substrate-v1.mjs`
- `schemas/runtime-profile.v0.1.schema.json`
- `fixtures/runtime-action-golden.v0.1.json`
- `lib/runtime-action-conformance-v0.1.mjs` for offline conformance tests only

Preserve these relative paths, or make an explicit reviewed import rewrite.
The reference runtime dependencies are exact `ajv` and `yaml` versions from
the root lockfile. Vendor updates are reviewed source changes; they do not
authorize a database migration, deployment, grant, or source activation.

Run the committed golden corpus in the consuming repository and compare full
outputs rather than snapshots generated by the same test invocation. Include
negative cases for optional unsupported tools, revoked authority, exhausted
budget, cancellation, missing ancestry and private governing rules.

## Select and index configuration

Load only an explicitly selected profile, an explicit project manifest entry,
or a trusted registry entry. Do not activate every `.yawn` file in a directory.
Use `spec_version` to select the exact parser. Unknown profiles may remain
inspectable source but cannot become runtime configuration.

```js
import { parseRuntimeProfile } from "@yawn-ai/dot-yawn-contracts/runtime-profile/v0.1";
import { buildRuntimeIndex, resolveForAction } from "@yawn-ai/dot-yawn-contracts/runtime-action/v0.1";

const profiles = explicitlySelectedTexts.map(parseRuntimeProfile);
const indexed = buildRuntimeIndex(selectedYawnId, profiles);
if (indexed.status !== "indexed") return hold(indexed.issues);
const result = resolveForAction(indexed.index, actionDescriptor, trustedHost);
if (result.status !== "resolved") return hold(result.issues);
```

`trustedHost` supplies authenticated registries/current stores and all checks
in the specification. No permissive sample verifier belongs in production.
The source-provided trust label, adoption reference and tool metadata are
claims the host verifies. Source instructions cannot change the grant target
or dispatch destination.

Persist the document, operational and action identities separately. Bind
decisions to `action_revision` and action dependencies. Keep evidence-frontier
revisions distinct from governing ancestry. Lateral evidence may change a
recommendation while never adopting a rule.

## Admission and receipts

Under the host's protected admission operation, reload current source/rule
state and grant/budget/stop snapshots, rerun preflight, compare the expected
action revision, reserve resources, and admit only the exact registered
handler. Use host-specific principal/resource/idempotency constraints.
An earlier screen, model recommendation or successful preflight is not a fence.

Record the exact configuration/action revision, skill source/version/digest,
capability binding and registry/tool-schema revision, current dependencies,
admission result and resulting execution receipt. Evaluate artifact completion,
delivery and world outcome separately. An uncertain delivery must not trigger
blind regeneration or resend of an already completed artifact.

Project permitted participant explanations and model context with
`projectRuntimeDisclosure` after enforcement. Do not expose a raw internal
index through a Rules page. A blocked result should explain that no currently
eligible method is available and offer a goal, method, authority or amendment
path; it should not declare the goal impossible.

An offline adapter test demonstrates only its tested path. Production
integration requires actual store concurrency, current-grant revocation,
stop/fence, private-disclosure and receipt evidence. Keep the
[status table](project-status.md#runtime-contract-stages) current as that
evidence arrives.
