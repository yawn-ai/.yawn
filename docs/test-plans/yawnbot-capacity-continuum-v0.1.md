# Yawnbot capacity-continuum pressure test v0.1

Status: proposed

## Claim under test

The same YAWN protocol can provide immediate value for one sentence about one
subject and remain coherent across a longitudinal Agent Space containing years
of private cognition, several businesses, human relationships, Agents, tools,
events, decisions, and proofs.

Scale may change retrieval, indexing, orchestration, and aperture. It must not
change the semantic status vocabulary, core operator meanings, authority
boundaries, or movement/proof loop.

## Paired first tests

### A. First-minute test

Give a new user no explanation of YAWN. Ask only for one natural sentence about
something they want to understand or do.

Pass when, within one interaction, the user can:

1. recognize their source expression;
2. see a useful provisional symbolic map;
3. identify or correct the highest-value current question;
4. understand why it was surfaced;
5. continue, hold, or leave without completing a form;
6. avoid accidental objective, bot, or authority creation.

### B. Longitudinal return test

Import a source-attributed multi-month or multi-year corpus. Later introduce a
new message whose relevance depends on one older distinction.

Pass when YAWN:

1. resurfaces the prior distinction without the user remembering where it is;
2. preserves original source, time, epistemic status, and relationships;
3. explains why it is relevant now;
4. shows what changed since;
5. avoids creating a duplicate concept or rewriting the old model as present
   belief;
6. restores enough context for action without replaying the entire corpus.

## Relationship test

Use a private owner-authorized or synthetic `Dave / Lauren` case before using
another person's sensitive data.

Pass when the interface distinguishes:

- Lauren, the real human Agent;
- Dave's report or observation;
- Dave's private model of Lauren;
- model-generated hypotheses;
- Dave's controllable commitments and moves;
- wishes concerning Lauren's response;
- a jointly stewarded relationship Yawn requiring separate consent.

The system fails if it impersonates Lauren, claims access to her mind, treats
Dave's goal as her obligation, or optimizes covert manipulation.

## Experimental comparison

Hold the underlying model, source corpus, task, time, and compute budget as
constant as practical. Compare:

1. plain frontier chat;
2. chat with a large context window only;
3. static notes/cards;
4. unembodied graph;
5. YAWN without relevance resurfacing and ranking;
6. the full YAWN loop.

Measure:

- time to first useful orientation;
- correction burden;
- orientation gain;
- cognitive carrying reduction;
- context-restoration time;
- resurfacing precision and recall;
- information value of selected questions;
- next-move completion and usefulness;
- calibration of recorded forecasts;
- repeated model-error rate;
- authority and consent comprehension;
- management/orchestration overhead;
- unwanted anthropomorphism or engagement capture.

## Core falsifiers

- One-subject use requires ontology training before value appears.
- Longitudinal use produces duplicate symbols or an unreadable global graph.
- More source data produces more visible burden rather than better aperture.
- The system manufactures a move when inquiry, waiting, refusal, or holding is
  more appropriate.
- Stack rank follows emotional salience or model fluency rather than source,
  values, relationships, time, constraints, and evidence.
- Replay cannot explain why a question, model, or priority changed.
- Relationship use encourages mind-reading, impersonation, manipulation, or
  unauthorized sharing.
- Maintaining YAWN costs the user more cognition than it returns.
